# dsh-mail-digest

[![CI](https://github.com/skyrocks/dsh-mail-digest/actions/workflows/ci.yml/badge.svg)](https://github.com/skyrocks/dsh-mail-digest/actions/workflows/ci.yml)
![license](https://img.shields.io/badge/license-MIT-blue.svg)

DeepSeek Harness 插件：**自动整理邮箱，每轮留一份能看的报告**。

定时抓 IMAP 邮件，逐封打标签、写一句话摘要；有来往的邮件并成线程，梳理时间轴做总结；
每轮整理生成一份报告（重点 / 需要你处理 / 线程进展），在右侧边栏或浏览器里看；跑完在 DSH 里弹通知。

## 为什么

邮箱的问题不是“看不到信”，是“要一封封读才知道哪封重要”。这个插件只回答三件事：
**这批邮件里什么是重点、哪些要你动手、哪几条线有进展**。其余只留标题，不占你的注意力。

## 报告长什么样

```
邮件整理 · 主邮箱 · 11-16 15:50
这周主要是合同收尾，其余是促销。
20 封新邮件 · 3 封待回复 · 1 封高优先级

## 重点
- 违约条款待法务确认：对方周四回复

## 需要你处理
- 合同条款 · 张三 · 11-01 17:00 · 待回复
  - 确认付款条件

## 线程进展
### 合同条款（5 封，11-01 → 11-09，本轮 +5）
**总结**：付款条件谈到 30 天，违约条款待法务。

## 这批邮件是什么
推广 15 · 工作 5 · 合同 5

## 其余（只列标题）
- 11-04 17:00 · 某商城 · 促销 3
```

同一份内容落三种文件：`reports/<id>.json`（面板用）、`<id>.html`（网页版）、`<id>.md`（纯文本）。

## 三个页签

| 页签 | 内容 |
| --- | --- |
| 报告 | 打开就是报告列表：未读标记，点一条在右侧边栏打开（面板里可「在浏览器打开」网页版），可删。右上角「立即整理」手动跑一轮；多个邮箱时顶部有账号切换 |
| 自动 | 开关 + 频率（每隔 1~168 小时，或每天 HH:mm）；一轮跑所有邮箱，每个邮箱各出一份报告 |
| 配置 | 邮箱列表（可加可删，删时可选连数据一起删）、选服务商自动填 IMAP/端口、账号与授权码、时间窗、标签清单 |

## 安装

```sh
dsh plugin --profile desktop add "link:/path/to/dsh-mail-digest"
```

或把目录拖进「插件 → 添加插件」。装完到「设置 → 邮件整理 → 配置」选服务商、填账号和**授权码**
（QQ / 163 / Gmail 都要用授权码，不是登录密码）。

## 用法

1. 配置里填好邮箱，点「测试连接」。
2. 点报告页的「立即整理」：抓邮件 → 打标签写摘要 → 梳理线程 → 出报告，几分钟后弹通知。
3. 也可以直接在对话里说「整理一下邮件」。
4. 想定时：自动页选「每隔 N 小时」或「每天 09:00」，保存后在「设置 → 定时任务」里能看到「邮件整理」。

## 工具

| 工具 | 作用 |
| --- | --- |
| `mail_status` | 邮箱列表（accountId）、标签、自动开关、各种计数 |
| `mail_fetch` | 抓一次邮件（不给 accountId 就抓全部；去重、重算线程、保留旧总结） |
| `mail_inbox` | 列未整理的邮件，带正文节选和所属线程 |
| `mail_read` | 读一封的全文 |
| `mail_thread` | 读整条线程的时间轴（写总结前必须先读） |
| `mail_file` | 写回标签 / 摘要 / 优先级 / 是否要回复 |
| `mail_thread_summary` | 写一条线程「到现在的总结」 |
| `mail_report` | 给一个邮箱出报告（可带 `overview` 和 `focus`） |
| `mail_reports` | 报告列表 / 读一份 / 删一份 |

## 数据放在哪

界面上不显示路径。默认根目录 `$DSH_HOME/mail-digest/`（即 `~/.dsh/mail-digest/`）：

```
mail-digest/
├── account.json    邮箱列表 + 标签清单 + 自动整理设置（不含密码）
├── messages.json   邮件：正文、标签、摘要、优先级、是否要回复
├── threads.json    线程：时间轴、参与人、到现在的总结
├── reports.json    报告索引：标题、时间、未读标记、文件路径
└── reports/
    ├── <id>.json   结构化内容（侧边栏面板读它）
    ├── <id>.html   网页版（「在浏览器打开」看它）
    └── <id>.md     纯文本版
```

- **授权码**不在文件里：每个邮箱一个键 `DSH_MAIL_DIGEST_MAIL_<账号ID>`，存在 DSH 凭据库。
- 文件 0600、目录 0700；邮件正文每封最多留 2 万字符。
- 备份就复制这个目录；换机器要重新填授权码。删掉目录等于清空数据。

## 安全边界

- 只读邮箱：不回信、不删信、不改已读（取信用 `BODY.PEEK`）。
- 授权码只进凭据库，不进配置文件、不回传界面。
- 删报告只删本地三份文件；这一批邮件退回「待整理」，下次整理重新出报告。

## 限制

- 不保存附件内容，只记文件名；抓取时会完整读取整封信。
- 单次最多抓 500 封，时间窗最大 3650 天。
- 自动整理依赖 DSH 的计划任务服务：Host 没运行时不会跑（漏掉的只补最近一次）。
- 线程靠邮件头和主题判断，跨主题的同一件事不会自动串起来。

## 开发

```sh
npm install
npm test
```

`test/store.mjs` 存储与归一化、`test/threads.mjs` 线程归并与总结接续、`test/service.mjs` 真 cordis Context 上跑服务、
`test/schedule.mjs` 计划任务（含每天定时）、`test/plugin.mjs` 九个工具的接线。全程不连网络。

> `npm install` 会把 peer 依赖（cordis / typert-protocol）装进本目录供测试用；运行时由 DSH 提供。
